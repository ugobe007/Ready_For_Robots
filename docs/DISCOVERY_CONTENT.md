## Editorial position

**ReadyForRobots shouldn't talk about robots. ReadyForRobots should talk about work.**  
The robots are how we look at the work.

Territory: **Robot Work** — where it exists, what it requires, which machines can do it, where humans still matter.  
Not: robot news, funding, humanoid demos, market-size takes.

## The publishing loop (content = sensor)

```
Discover Robot Work
  → identify most surprising / useful findings
  → turn into a story
  → publish (unique src=)
  → measure which work creates curiosity
  → /experiment
  → learn which robot/capability people submit
  → feed that demand back into discovery
```

Audience reaction is **market curiosity before signup**.

Example signal: hospital medication-cart movement gets 8× engagement vs generic AMR tote post → that work category has energy — before anyone registers.

## Three formats only (start here)

Market reports + Robot Job Index **wait**.

### 1. Today's Job for a Robot

Daily or several×/week. Very short. **Job is the headline — not ReadyForRobots.**

```
TODAY'S JOB FOR A ROBOT

Return medication carts between the pharmacy and patient units
Hospital · Newark, Delaware

Hospital pharmacy technicians exchange medication carts throughout the day.
Robot work: move loaded/empty carts along repeatable internal routes.
Still unknown: cart interface, elevator use, traffic, security requirements.

Could your robot do this?
→ /experiment?persona=oem&src=job_<slug>
```

### 2. We Went Looking for Work for…

High-engagement feature. Show finds **and** rejects.

```
We went looking for work for a warehouse AMR. We found 67 jobs.
Unexpected: hospital supplies · pharma totes · mfg kits · apparel carts · …
Insight: AMRs aren't warehouse robots. They're movement robots.

We went looking for work for a floor-cleaning robot.
25 searches · 16 jobs · hospitals, airports, malls…
Didn't qualify: carpet extraction · restrooms · outdoor lots · generic janitorial.
```

Makes RFR look intelligent, not promotional.

### 3. Human Work → Robot Work

Thought leadership from RDD architecture.

```
What part of a warehouse order selector's job should a robot actually do?

Human: find SKU · pick case · verify product
Robot: carry accumulated order · move between zones · stage completed order

Insight: Don't ask whether a robot can replace a job.
Ask which physical tasks inside the job the robot should own.
```

## Content → Work funnel (what to measure)

Vanity (secondary): impressions · likes · followers.

**Valuable chain:**

```
Work story published
  → /experiment visits          (rdd_experiment_view + src)
  → robot submissions           (rdd_robot_submitted)
  → job engagement              (rdd_job_viewed · 3+)
  → See All                     (rdd_see_all_clicked)
  → signup
```

Eventually learn e.g.:

- Hospital cart content → 19 submissions · 7 See All  
- Palletizing → 41 visits · 2 submissions  
- Spot inspection → fewer visits · higher conversion  

Content discovers **which robot work people care about** — not marketing outside the product.

Also still segment: OEM vs distributor vs integrator **and** content topic → submission family.

## Quality gate

> What did we discover here that the reader probably didn't know before reading?

If nothing — **don't publish.** Commentary (“robots can move totes”) ≠ ReadyForRobots discovery (named work + explicit responsibility observed).

## Branding

Job is the headline. Don't over-brand every graphic or lead with #RobotJob / ReadyForRobots. Earn association by repeating discoveries. Don't explain LWO / E1 / ontology — only: what we found · why it matters · robot opportunity · unknowns.

## Cadence

Write one → publish → learn voice → write next. Editorial learning ≠ product experiment change.
